# Anima 原创角色（OC）分支

## 仅在以下条件读取

当前请求含用户自创角色、为尚无稳定公开作品身份的人物设计形象，或连续多图需要维持这类人物的外观时，读取本文件。纯公开角色请求不读取。公开角色与 OC 同框时，只对 OC 应用这里的规则；公开角色仍以“角色名 (作品名)”为默认身份锚。用户指定的 OC 必须保留，不能自行替换成公开角色。

本文件补充 anima-prompt 的 A/B/C 模板。模板、画师、质量、安全和负面提示词仍由主文件决定。

## 先建立 OC 视觉设定

OC 自造名字仅作为设定表或分镜中的索引，通常不能独自锁定画面外观。先确定**稳定身份**，再确定**本帧状态**。如果用户已经给出设定，逐项沿用；用户要求设计新 OC 时，再按题材补齐辨识度所需的空项。不要把个人偏好当成所有 OC 的默认外观。

稳定身份设定可覆盖以下维度，按角色需要选择具体值并保持一致：

| 维度 | 具体化方式 |
|---|---|
| 身形与比例 | 身高感、体型、肤色；体型有剧情或服装意义时写清 |
| 头发 | 发色、长度、主要发型、刘海形态 |
| 眼与面部 | 瞳色、显著眼型、稳定的面部标记 |
| 轮廓特征 | 兽耳、尖耳、角、翅膀、义肢等身份特征 |
| 签名物 | 持续佩戴的发饰、首饰、纹身或核心道具的外观与位置 |
| 常服 | 主要衣件的颜色与款式；若会随剧情换装，放进状态表而非身份块 |

优先锁定最能认出此 OC 的 2–4 个特征，其余维度服务于清晰度。记录完整设定有助于创作，但单张 prompt 只写本帧可见、可影响识别的部分；背面镜头不为显示眼色而强行改变机位，面部特写不硬塞不可见的鞋袜。低显著性细节可用具体位置短句说明，避免堆无效标签。

泛称改为具体值：long hair 可细化为 silver hair, very long hair, blunt bangs；school uniform 改成白衬衫、红领结、蓝色百褶裙等实际衣件。具体值来自用户设定或当前设计决策，不能凭示例套用。发型和刘海若是辨识点，跨图保持同一表述。

## 固定身份块 + 当前状态槽

为每位 OC 存一份简短的固定身份块。第一次确定后，连续图中尽量逐字复用，除非故事明确改变了外观。衣服、姿势、表情、持具、伤痕等会变的东西进入当前状态槽，更新时替换旧状态，不把互斥状态叠加。

~~~text
OC A 固定身份块：
[发色与发型], [瞳色与显著面部特征], [肤色与身形], [1–2 个签名特征]

本帧状态槽：
[当前服装与裸露/遮挡状态], [姿势与主动作], [表情与视线], [可见道具的位置], [场景与光线]
~~~

**模板 A/B/C 中的“角色身份”位置填固定身份块，人数 tag 仍放在模板层**；状态槽按对应模板放进动作、服装和场景层。OC 的名字可以保留在工作表与文件名里，除非它本身是模型已学会的公开身份标签，否则不把名字当作视觉锚。

若剧情永久改变发型、印记或身体特征，建立“变更后”的身份块版本，并从对应页开始使用。暂时湿发、披风脱落、转身或表情变化属于当前状态，不改固定身份。系列图可用一张简短状态表记录每页的服装、道具与关键变化：

| 页/图 | 固定块版本 | 本帧服装 | 可见签名物/道具 | 新变化 |
|---|---|---|---|---|
| 01 | A | 初始服装 | 发饰佩戴中 | 无 |
| 02 | A | 外套脱下 | 发饰仍可见 | 外套在椅上 |
| 03 | A2 | 新造型 | 发饰已移除 | 刘海与发饰状态更新 |

状态表是编写 prompt 的辅助，不要求向用户暴露为固定交付格式。

## 跨图一致性与可见性

- **当前状态可见**：服装按衣件写当前穿着或移除结果；脱下的件只有剧情需要其落点时才入画。露出状态与残留衣件不要互相矛盾。
- **签名特征连续**：可见且仍在角色身上的签名发饰、角、印记等持续写；被遮挡时可省略画面描述；已移除时更新状态。
- **道具独立于身份**：手持剑、戒指、怀表等只在可见或动作必需时写，不为跨图一致性强制入画。关键道具要保持简洁且一致的形状、颜色、位置和归属。
- **视角与表情**：远景只保留可辨轮廓，特写才展开细小面部特征。表情和视线是每帧变量，不能反过来改动稳定五官。不要让同一只手、眼或嘴同时承担互斥动作。
- **服装版本**：常服可作为默认状态；换装、破损或脱衣后使用新状态，不在后续 prompt 里继续引用旧衣件。用户要求复原或再次穿上时可切回旧状态。

## 多个 OC 与混合场景

多个 OC 同框时，各有自己的固定身份块与当前状态槽。分段描述，每个角色的动作和所处位置单独标明。外观相近的两人可在发型轮廓、配色、衣服剪影或身形中拉开至少两项明显差别；不要通过替换成已知角色来制造区分。

OC 与公开角色同框时：

~~~text
1girl, [OC 固定身份块], [OC 当前状态]
1boy, [公开角色名 (作品名)], [该公开角色本帧动作或用户指定变化]
[两者前后位置、接触点和场景]
~~~

仅当公开角色的外观变化由用户明确要求，或本帧状态必须表现时，才追加具体外观词；不要把 OC 的全维度设定规则扩散到公开角色。

## 针对性的负面提示

只压制本次画面实际出现过或高概率发生的偏差。例如某个签名发饰被错误画成头巾，可加 headscarf, veil；深色衣服常被当前明亮场景洗浅，可排除对应浅色衣件；多个 OC 融合时加 cloned face, merged bodies。不要为每个未出现的问题列一整套负面词。正面要求的衣物、道具、镜面、人数或表情，不能同时在负面出现。
