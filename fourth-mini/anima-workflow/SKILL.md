# 工作组织

每个项目保留可追溯的输入、输出和版本。多轮迭代时，为每一轮和每个变体建独立目录；原图、最终成片、淘汰图及脚本或日志分开存放。目录名称包含项目、轮次和变体即可，按运行环境选择路径，不依赖固定的本机目录或自动归档脚本。

建议结构：

```text
<project>/
  inputs/
  runs/<round>/<variant>/
  final/
  rejected/
  notes.md
```

`notes.md` 记录当轮目标、使用的 skill 版本、提示词或配置变化、样本编号、观察与下一步。生产图和对比图不要混到同一层，便于回看和复现。

# 对比与迭代

比较两个 skill 或方案时，先确定评价维度，例如人物可辨认度、事件可读性、画面感染力或提示词遵循程度。对照样本尽量保持相同主题、角色、画幅、模型设置和种子；只改变想检验的因素。如果允许方案自行决定画师或模板，就把这些也视为方案的一部分并明确记录。

小样本先找明显问题，再决定是否扩充测试。每轮读图、记录失败原因、修改一个主要假设，再生成验证；出现退步时回到最近有证据支持的版本。保留可恢复的版本与简短变更记录，不把一次偶然成功当作稳定结论。

批量提交时按所用生成器的正常队列机制操作，记录任务 ID 与输出对应关系。共享队列中的其他任务保持原状；若生成服务异常，先核对状态和任务归属，再按当前环境的运维方式处理。

# 读图审查

按页查看实际图像，并结合提示词或图像元数据核对四件事：

1. 关键人物、动作与道具是否出现且归属正确。
2. 构图、人体和空间关系是否清楚。
3. 场景是否符合分镜的时间、地点和情绪。
4. 这一页的叙事信息能否让读者读出。

数量、归属或接触点看不清时放大确认。长篇可分批审查，再对有问题的页重画；重画后仍须看新图是否解决原问题并与前后页接得上。

# 对白与成片

写台词时读取 [references/dialogue-style.md](references/dialogue-style.md) 入口，按当页语气选择对应篇目，再结合 [references/dialogue-style-common.md](references/dialogue-style-common.md)。对白给人物声音、态度和关系；旁白只补画面无法直接交代的时间、地点或画外信息。用户指定的语言和语体优先。

对白框、思考泡和旁白框各有不同功能。先在页图上确定说话人、阅读顺序和避让脸部及关键动作的位置，再写句子并排版。逐页检查文字是否盖住画面焦点、气泡尾巴是否指向正确人物、跨页声线与剧情是否连续。最终交付包含成片；原图和淘汰版保留在独立目录，方便追溯。
